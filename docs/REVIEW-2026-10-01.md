# cccodex 更新・レビュー記録（2026-10-01）

ユーザーの依頼により `fable-harness` を削除し、cccodex の既存実装を
Claude Code / `claude-opus-5-5` / `max` でレビューした。CLI応答の報告モデルは
`claude-opus-5-5`。モデルの自動切替は行っていない。

[Claudeレビュー原文](REVIEW-2026-10-01-claude.md)は更新前ソースへの独立レビュー。
以下は Codex が現物・ローカルCLI・公式ドキュメントと照合し、修正した記録。
更新後全体への2回目のClaudeレビューは行っていない。

## 更新

- `fable-harness` を削除。2エージェント・2コマンド・3フックを維持。
- marketplace/plugin を 0.4.0 に揃え、削除済みロールの説明を更新。
- 変更範囲監査を内容ハッシュ・モード・リンク先・存在の比較へ変更。
  既に変更済みだったファイルの追加編集・削除も検出する。
- 未追跡ディレクトリ内のファイルとリンクをバックアップする。
  リポジトリルートを基準にし、絶対パス・`..` を含むscopeは拒否する。
- タスク開始時点のコピーと差分を取り、ユーザーのWIPと委任による変更を区別する。
- 自動fallback・ストールによる自動再起動を削除。失敗ログを保持し、
  初回成功後の修正resumeを最大1回に制限。実際のmodel/effortをresumeにも渡す。
- background Bash + Read/TaskStop を使う指示へ変更し、実行固有のログ・結果パスを出力。
- 各実行後・検証後に監査する。帰属が不明な変更や復元コピーのない変更を自動で戻さない。
- `/codex-review` のターゲットと追加プロンプトの排他を処理。
  追加指示がある場合は対象diffを渡してoracleでレビューする。
- hook のパスを引用し、空白を含むインストール先に対応。
- `CCCODEX_MODEL` / `CCCODEX_EFFORT` で明示的な設定変更を可能にした。
  既定値は元の `gpt-5.6-sol` / `max` を維持。

## 指摘の判断

| Claudeの指摘 | Codexの判断・対応 |
| --- | --- |
| H1: WIP追加編集をstatus集合で検出できない | 再現・修正。内容等の比較と回帰テストを追加。 |
| H2: 同期処理では停止・再試行の管理が曖昧 | background task IDを使う契約へ変更、自動再起動を削除。 |
| H3: 広すぎるfallback判定・ログ上書き | fallback自体を削除。 |
| M1: シェル変数・ログパス・thread IDが後続呼出しに伝わらない | 明示出力と値の再設定、JSONイベント解析へ変更。 |
| M2: SubagentStopのadditionalContext非対応の疑い | 不採用。現行[公式hooks契約](https://code.claude.com/docs/en/hooks#add-context-for-claude)は対応を明記。 |
| M3: サブディレクトリ・リンク経由cwdで不一致 | root/realpathで統一。回帰テスト追加。 |
| M4: cleanな範囲外ファイルの復元元がない | コピーがなければ報告。HEADからの復元は採用しない。帰属不明時も自動復元しない。 |
| M5: HEAD基準diffでWIPが混ざる | タスク開始時点のコピーと比較する指示へ変更。 |
| M6: reviewの引数互換性と対象のtriage | CLI引数エラーを実測して修正、対象別のtriageを明記。 |
| M7: version/description不整合 | 0.4.0へ整合。 |

Read/TaskStop の契約は[公式Tools reference](https://code.claude.com/docs/en/tools-reference)で確認。

## 残る制約

- Codexモデルへの認証済み実呼出し、Claudeからのbackground taskの終了/停止、
  プラグインを有効化した実セッションでの委任・resumeは未検証。
- 実装の一部はMarkdownでの指示。scope/Git操作の制限は強制的な隔離ではない。
- 同一checkoutの同時実行は最新manifestの推定で監査対象がずれる可能性が残る。
  warn-onlyであり、自動復元はしない。
- submodule/ディレクトリ内部の変更、ignoredファイルの範囲外変更は別途検証が必要。
  大規模リポジトリでは全tracked/untrackedファイルのハッシュ計算コストに注意。
- プラグインのインストール・有効化は未実施。
